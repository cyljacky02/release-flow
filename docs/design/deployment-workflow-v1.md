# 第一版設計共識

狀態：使用者已確認本設計並授權開始第一版實作。此文件描述目標契約，不代表所有能力已完成；目前實作與驗證限制見 README 及操作指南。

第一版互動介面採 PowerShell 文字選單與確認提示，不先實作全螢幕 TUI。

## 目的與分工

將 developer 提供的人工部署流程轉成可執行、可驗證且可留下紀錄的 PowerShell 工作流。正式部署前仍沿用既有 review 與核准流程，另一部門的部署執行者再確認並執行指定計畫。

- Developer 準備應用、工具、部署定義、已知的非秘密環境設定，並在 SIT／UAT 驗證。
- 部署執行者執行已核准的來源版本、目標版本及部署規則，不自行核准計畫外異動。
- 工具不建立新的公司核准系統，也不宣稱自身能證明 ISMS／ISO27001 合規。
- GitLab 第一版只建置、打包及投遞；正式換版由部署執行者啟動。未來非互動部署仍使用相同核心。

## 範圍

- 每次操作處理單台 Windows 機器上的一個部署單位，可包含多個相依的 Windows services；同一 repo／branch 可管理多個部署目標。
- 各目標獨立換版、獨立復原，第一版不提供跨機共同成功保證；允許逐台完成及暫時版本混用。
- 接受維護窗口；可提前完成的下載、解壓與驗證在停機前進行。
- 管理應用檔案、服務啟停與應用健康檢查。
- 受管理的非秘密應用設定納入換版、備份及復原；現場保留設定、秘密與執行期資料不得任意覆蓋或刪除。任何檔案都不因 artifact 缺少對應內容就自動被刪除。
- 第一版不納入資料庫 migration、跨機協調或任意有副作用的客製部署腳本。
- 客製化先限定唯讀的前置與健康檢查；其他需求須先定義失敗與復原責任。

## 交付與信任

- 版本產物包含完整版本管理檔案與完整 manifest；目標機器計算實際差異。
- 部署套件包含版本產物、具版本的共用 PowerShell 核心及專案部署設定。
- 應用內容與工具分開放置；工具從受保護的工作區執行，不隨應用檔案被覆蓋。
- developer 可準備正式環境的非秘密參數；秘密留在目標環境。
- 整份套件的程式碼與設定納入既有審查，核准後固定內容摘要。
- 第一版信任受控 GitLab pipeline 與受保護的投遞管道，不要求簽章；hash 不等同來源驗證。
- 工作區保留本次工具、設定與操作紀錄，復原不依賴原始投遞 ZIP 仍存在。
- 保留已驗證工具版本；工具與復原資料需明確檢查相容性，另提供人工復原指引。

## 換版契約

1. 核對指定來源／目標版本、核准部署規則與套件完整性。
2. 檢查現場、權限、空間、服務必要狀態及工作區可寫入性。
3. 產生並呈現實際換版計畫；現場漂移或計畫外異動阻擋並回報。
4. 部署執行者再次確認；開始異動前重新核對現場與計畫未變。
5. 按明確設定的停止順序停止服務；停止失敗不改正式檔案。
6. 完成復原集與完整快照後才可套用正式檔案異動。
7. 按設定的啟動順序恢復應運行的服務，執行服務狀態與應用健康檢查。
8. 保存結果並生成可讀報告與 JSON；快照 ZIP 可延後生成。

正式模式不提供任意選版。部署舊版本需另一份核准指令；SIT／UAT 可提供自由選版模式。若公司要求先審正式現場逐檔差異，需改採先產生計畫、送審、再執行的流程。

版本與受管理內容已符合目標時回報無需換版，不停服務、不建立新快照；未完成操作及漂移不可藉由重跑跳過。

## 檔案與備份

- 明確區分版本管理範圍與保護範圍；只刪除原本受管理而目標版本已移除的檔案。
- 未知檔案不自動刪除。
- 第一版支援一般檔案及目錄，拒絕受管理範圍的 reparse points、artifact 路徑逃逸及大小寫衝突。
- 保留既有檔案 ACL，新檔案採部署目錄權限政策；復原資料保存必要中繼資料。
- 復原集保存新增／覆蓋／刪除紀錄與被取代檔案的實際原內容。
- 快照完整保存停止相關服務後的版本管理範圍，不涵蓋資料庫與執行期資料復原保證。
- 工作區及備份在正式應用目錄外，可指定不同磁碟；定位為換版復原而非災難復原。
- 空間不足阻擋換版，不在換版中自動清理；清理是獨立、可預覽並需確認的操作。
- 不允許刪除未完成操作所需復原資料，其他保留天數／份數可配置。

## 復原與中斷

- 升版及降版均建立復原集，撤銷方向是本次換版前的實際現場。
- 成功換版後亦可撤銷，但僅限最近一次尚未被後續換版取代的操作，且資料完整、現場檢查及授權政策允許。
- 換版後出現計畫外異動時阻擋復原，不由部署執行者強制覆蓋。
- 預設只在尚未嘗試啟動目標版本服務前允許自動還原；啟動後的復原按事先授權政策由人員確認。
- 檔案還原不保證撤銷資料庫寫入或其他外部副作用。
- 復原包含檔案、換版前服務運行狀態及原版本健康檢查；部分完成需明確報告。
- 同一部署單位限制一個執行者，持久化操作紀錄；程序中斷後先檢查未完成操作，禁止直接開始新換版或盲目續跑。
- 復原失敗保留資料與現場，檔案狀態未確定時不啟動服務，要求人工介入。
- 必要操作紀錄無法持久化時停止後續異動；已驗證成功但衍生報告生成失敗時，標示報告待補而非自動撤銷。
- 報告記錄操作者、變更參考、版本、核准計畫、實際異動、服務操作及驗證／復原結果，不記錄秘密或設定內容；提供明確退出碼。

## 多目標建置與投遞

- 預設同一 commit build 一次，共用版本產物；只有確實影響編譯輸出的差異才拆建置變體，不按機器數量重複 build。
- 預設一個 pipeline 共用 build job，每個部署目標有獨立的 package／delivery jobs，可單獨投遞與重試；不要求每台獨立 pipeline。
- 各目標套件在獨立組裝目錄使用同次 build 產物及同一 commit 的目標非秘密設定，重新產生套件清單與摘要。
- 只帶指定目標的設定，不先投遞其他目標設定再刪除；秘密不包入套件。
- 以明確目標識別選擇設定；套件記錄目標，執行時核對避免誤投／誤部署。
- 區分部署定義、受管理應用設定及現場保留設定；受管理設定的異動也納入核准計畫與復原，報告不輸出設定值。
- 本地 DEMO 與專案接入 skill 亦須支援多目標組裝及選定目標投遞，仍共用同一部署核心。

## 首次納管

現場缺少 manifest 時走獨立的基準建立流程：掃描實際受管理內容，由 developer 核對並經既有流程核准後採用。掃描本身不證明版本正確。

## 第一版本地驗證與 GitLab

第一版先提供純本地 PowerShell 端到端 DEMO／快速測試，不要求 Docker、容器或 VM。

本地流程：build → package／manifest → 投遞至指定路徑 → 部署執行入口 → 確認 → 備份 → 套用 → 驗證 → 報告 → 復原示範。

- 檔案操作、ZIP、manifest、備份、換版及復原使用真實隔離目錄。
- 服務控制與健康檢查預設模擬，可注入停止／啟動等失敗情境，不操作既有真實服務。
- 本地與 GitLab 共用權威 build／package 命令、產物格式與部署核心；入口各自處理變數、路徑及 artifact 傳遞。
- 同時交付正常 GitLab jobs／pipeline 設定及操作文件。
- 本地成功不等於遠端 pipeline 或真實服務、ACL、檔案鎖定已驗證。Windows VM 整合驗證延後，程序中斷測試不宣稱證明抵抗斷電。
- 快速測試涵蓋升／降版及撤銷、新增／覆蓋／刪除、漂移與前置失敗、套用／中斷／復原失敗、重複／並行執行及保護資料不被誤改。

## 專案接入 Skill

Skill 是 developer 準備交付物的輔助流程，不是目標機器執行依賴。

- 探索專案 build、輸出內容及既有 pipeline，未定需求先詢問。
- 使用具版本的共用核心，產生專案配置與必要接合腳本，而非每個專案重寫復原核心。
- 同時產生本地入口、GitLab jobs、部署設定與操作文件，明列兩者差異。
- 在隔離本地 DEMO 目錄驗證；真實 build 先確認依賴與副作用。
- 遠端修改、憑證、正式路徑投遞及正式换版需另外明確授權。
- 報告實際已驗證及未驗證項目，不把本地成功當作遠端或正式環境成功。
